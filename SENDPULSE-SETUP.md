# SendPulse: підготовка підключення

Це перший пакет виправлень інтеграції, а не завершений запуск.
Зміни потребують узгодженого налаштування Render і SendPulse до злиття.

## Контракт запиту

У Render задайте `TELEGRAM_BOT_USERNAME`, `SENDPULSE_FLOW_ID` і
`SENDPULSE_API_SECRET` (випадковий секрет щонайменше з 32 символів).
Секрет не додавайте в GitHub, HTML, URL або повідомлення бота.

У SendPulse створіть змінні `scan_token`, `Phone`, `pdfUrl`, `brand`,
`score`, `tier`. Ідентифікатор підписника вибирайте з системних змінних
редактора; не підставляйте ім'я, username або текст із відповіді користувача.

1. Вхід у ланцюжок за посиланням сайту зі змінною `scan_token`.
2. Очікування `Phone or Contact`, опція `Only via Share Contact`; зберегти в `Phone`.
3. Після контакту — блок API Request:

   - POST `https://ai-visibility-backend-ybg2.onrender.com/api/sendpulse-report`
   - `Content-Type: application/json`
   - `X-SendPulse-Secret`: той самий секрет, що в Render.
   - JSON нижче; значення `contactId` вставити через системну змінну редактора.

```json
{
  "token": "{{scan_token}}",
  "phone": "{{Phone}}",
  "contactId": "<SYSTEM_SUBSCRIBER_ID>"
}
```

Не надсилайте буквальний `<SYSTEM_SUBSCRIBER_ID>` — це заповнювач.
Сервер довіряє контакту тільки від авторизованого ланцюжка; він не звертається
до Telegram для окремої перевірки номера. Збір власного контакту забезпечує
правильно налаштований блок Share Contact.

4. З відповіді зіставити `pdfUrl` → `pdfUrl`, а також `brand`, `score`, `tier`.
5. Блок «Файл» з URL `{{pdfUrl}}`.
6. Тег лід-магніту `ai_visibility`; далі — налаштована серія повідомлень.

Помилки: 400 — перевірити контакт/змінні; 401/503 — налаштування інтеграції;
404 — запропонувати повторний скан; 409 — звіт належить іншому контакту;
500 — дозволити повторний запит. Помилка API не повинна вести у блок файла.

Повторний запит того самого контакту повертає той самий PDF до завершення
терміну життя результату. Це означає «PDF підготовлений», а не підтвердження,
що користувач прочитав або навіть отримав документ у Telegram.

## Старий бот

Коли задано `SENDPULSE_FLOW_ID`, сервер повертає 410 для старих маршрутів
webhook/setup/cron/broadcast і видачі email-звіту. Вимкніть зовнішній cron,
що викликав старий прогрів. Керування ботом має залишатися у SendPulse.

## Що ще потрібно до робочого запуску

- Перевірити фактичний сервіс, тариф і сховища в підтвердженому просторі Render.
- Замінити пам'ять процесу постійним сховищем результатів/прив'язок. Поточний
  термін — одна година; перезапуск процесу все ще втрачає результати.
- Додати термін дії та очищення PDF. Зараз `/reports` — локальні файли за
  непередбачуваними, але публічними посиланнями; ця зміна не закриває їх.
- Дані аналізу досі повертаються в браузер і лише приховуються інтерфейсом.
  Цей пакет захищає виклик PDF, але не перетворює аналіз на повністю закритий ресурс.
- Перевірити в SendPulse збір контакту, повторний вхід, невдалу відправку,
  відписку та зупинку серії після заявки на консультацію.
- Перевірити службові маршрути старого сервера перед публічним запуском.

## Локальна перевірка

`node --test test/sendpulse-report.test.js`

Тести не звертаються до AI, Telegram, CRM чи реальних підписників.

## Звірка зі скриншотами поточного ланцюжка

- API зараз з’єднаний зі звичайною кнопкою «Отримати результати звіту».
  Перепідключити його до зеленого виходу блоку «Ввід даних» після контакту.
  Звичайна кнопка не повинна обходити отримання телефону.
- Відповідь `pdfUrl` зберігається в `pdfUrl`, а блок файла використовує
  `PDFURL`. Вибрати у блоці файла саме `pdfUrl` зі списку змінних.
- Для відповіді сервера з полями score/brand/tier/pdfUrl потрібна вкладка
  «Зберігати значення». «Відправляти повідомлення» призначена для масиву
  карток і для цього одиночного PDF не потрібна.
- Успіх API → повідомлення з балом → файл. Помилка API → пояснення,
  а не повідомлення з порожніми brand/score/tier. За потреби після API
  додати перевірку, що pdfUrl і brand непорожні.
- Повний тест починати зі свіжого скану на сайті й кнопки Telegram.
  Звичайний /start не передає код нового аналізу. Перевірити scan_token
  у картці конкретного тестового підписника.
- Старий код main видаляє токен після API-запиту: успішна кнопка
  «Перевірити запит» могла вже використати його. Для проходження старого
  ланцюжка потрібен новий скан. Ця гілка додає повторну видачу.
- У поточному запиті показано chatId. Після впровадження цієї гілки
  передавати contactId із системного ID підписника й додати секретний
  заголовок. Наявність {{contact_id}} на скрині не підтверджує, що ця
  змінна системна: перевірити через список змінних редактора.

Назви Phone і pdfUrl збережені відповідно до наявного ланцюжка; нові
phone/pdf_url створювати не потрібно. Налаштування в кабінеті SendPulse
за скриншотами не змінено — це інструкція для наступного кроку.
